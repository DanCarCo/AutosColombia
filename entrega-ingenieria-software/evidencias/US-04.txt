Fecha de ejecución: 15/11/2026
Versión: sistema con roles (migración 0005, ADMINISTRADOR / OPERADOR) - segunda ejecución del plan
Entorno: API http://127.0.0.1:8000 · Frontend http://127.0.0.1:4200 · PostgreSQL 16 aislado (Docker, base de pruebas)
Credenciales y tokens ocultos en esta evidencia.

REGISTRO:
POST /auth/login cuerpo={"usuario": "", "password": "<redactado>"} [sin sesión] -> HTTP 422 {"detail": [{"type": "value_error", "loc": ["body", "usuario"], "msg": "Value error, El campo debe ser texto no vacío.", "input": "", "ctx": {"error": {}}}]}   # usuario vacío

ESTADO: Aprobado
RESULTADO: La interfaz indica «El usuario es obligatorio.» y «La contraseña es obligatoria.» sin enviar solicitud; el servidor también rechaza con 422 las tres variantes y no crea sesión.
